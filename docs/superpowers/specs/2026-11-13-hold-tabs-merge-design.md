# 庫存分頁整併（設計）

日期：2026-11-13　實作者：Claude Code　狀態：待使用者核可

## 為什麼做

使用者覺得庫存的功能重複。現在庫存有兩層分頁：外層 5 個（即時損益、持股分析、風險、總經敏感度、交易紀錄），
「交易紀錄」點進去又有 7 個（總覽、交易紀錄、績效、配置、股利、融資、論點），其中一個還同名。
同一類資訊散在兩層：損益在「即時損益」和「總覽」，佔比在「即時損益」「持股分析」「配置」，
下跌試算與再平衡在「風險」和「配置」各有一份。

## 目標

- 庫存只剩一排主分頁，同一類的內容放在同一個主分頁底下。
- 每個現有功能都還在、算出來的數字不變。

## 不做（這次）

- 不合併重複的計算（兩個再平衡、兩個下跌試算、三處股利都保留），之後每組另開 PR。
- 不動兩份持股資料（舊庫存 `kline:watch:hold`、交易紀錄 `kline:pf:v1`）與資料來源切換。
- 不動存股頁「我的庫存股息」、今日重點、盤中監控等其他讀庫存的地方。

## 絕對不能發生

- 改寫、搬移或清除任何 localStorage；不新增資料鍵。
- 任何現有功能變成找不到入口。
- 為了讓測試通過而刪測試或放寬斷言。

## 做法比較

1. **只整理分頁（採用）**：兩層併成一層，計算與存檔不動。風險最低；同一個主分頁下仍會看到兩份再平衡、兩份下跌試算。
2. 連重複計算也各留一份：畫面最乾淨，但會改績效與風險算法，需要獨立審查並逐項決定口徑。延後，分批做。
3. 連兩份持股資料也併成一份：會動到使用者已存的持股，這次不做。

使用者選 1（「照你的建議做」）。

## 新的分頁

```
庫存：總覽｜持股｜績效｜配置與風險｜股利｜論點｜交易紀錄
        持股        → 損益｜屬性分析
        配置與風險  → 配置｜風險｜總經敏感度｜融資
```

| 主分頁 | 子分頁 | 內容（原本的頁面） | 需要交易紀錄 |
|---|---|---|---|
| 總覽 | — | 交易紀錄的「總覽」；「報告（可列印）」按鈕仍在這裡 | 是 |
| 持股 | 損益 | 「即時損益」 | 否 |
| 持股 | 屬性分析 | 「持股分析」 | 否 |
| 績效 | — | 「績效」 | 是 |
| 配置與風險 | 配置 | 「配置」（含目標配置與再平衡、壓力情境） | 是 |
| 配置與風險 | 風險 | 「風險」 | 否 |
| 配置與風險 | 總經敏感度 | 「總經敏感度」 | 否 |
| 配置與風險 | 融資 | 「融資」 | 否 |
| 股利 | — | 「股利」 | 是 |
| 論點 | — | 「論點」 | 是 |
| 交易紀錄 | — | 交易清單與新增／修改 | 是 |

需要交易紀錄而還沒建立時，顯示現有的「從現有庫存建立／建立空白」說明頁（行為不變）。

## 怎麼做（實作者的決定）

- **內部狀態不改**：仍是 `W.holdView`（pnl／ana／risk／macro／tx）加 `W.lg.view`（home／tx／perf／alloc／div／margin／thesis／report）。
  新增一張對照表與兩個小函式：由狀態算出「目前在哪個主分頁、哪個子分頁」，以及點分頁時要設成哪組狀態。
  這樣 `pf-*.js`、`ledger-ui.js` 裡判斷目前頁面的程式（`W.holdView === "tx" && W.lg?.view === …`）都不用改。
- **畫面**：`watch.html` 的 `#hvSeg` 改畫 7 個主分頁；`ledger-ui.js` 的 `lgViewSeg()` 不再畫第二排主分頁，
  只在「配置與風險」時畫子分頁。「持股」「配置與風險」的子分頁用同一個小元件，放在內容上方。
- **記憶**：沿用現有的 `watch:hv`（值的集合不變，舊值照樣有效）。`W.lg.view` 目前只在記憶體，維持現狀：
  重新整理後，原本在績效／配置／股利／論點／交易紀錄的會回到總覽。
- **預設頁**：第一次進來仍是「持股 → 損益」（沒有交易紀錄也能用）。
- **台股／美股切換**（`#holdSeg`）：和現在一樣只在持股、風險、總經敏感度出現。
- **編輯庫存／截圖匯入／匯出**：只在「持股」出現（現在是所有非交易紀錄頁都出現）。
- **桌面寬度**：維持現有規則（原交易紀錄底下的頁面用全寬，其餘是「清單＋個股頁」）。
  因此「配置與風險」裡，配置／融資是全寬，風險／總經敏感度是雙欄，切子分頁時版面會換。先照現況，列為驗證重點；
  若看起來太跳，另開 PR 把風險、總經敏感度改全寬。
- **資料來源列**（「持股來自交易紀錄／舊庫存」與切換鈕）：行為不變；「看交易紀錄」按鈕改成帶到主分頁「交易紀錄」。

## 測試與驗收

- 新測試（假資料，390 與 1280）：只有一排主分頁；11 個頁面都點得到且內容是對的那一頁；
  主分頁與子分頁的選取狀態正確；重新整理後記得主分頁；只有舊庫存時，需要交易紀錄的頁面顯示建立說明、
  持股／風險／總經敏感度／融資照常；390 寬不橫向溢出、分頁按鈕高度不小於現有門檻。
- 既有測試：所有改過導覽的 e2e 檔，加上 `pf-mobile`、`pf-tablet-kbd`（改到共用檔的規定）、`unit.test.mjs`。
- 完整測試以同一 head SHA 的 CI `test` 為準。
- 介面修改：需要 Antigravity 在 390／1280 用預覽實際操作驗證。
- 合併：等使用者明確說可以合併（不適用低風險例外，因為改到 HTML／JS）。
