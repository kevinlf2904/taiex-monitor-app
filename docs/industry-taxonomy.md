# 產業分類：三套分類的定位與規則

KLineLab 同時用到三套「產業」分類。三套互相連結，但不互相取代、不合併成一套。改資金雷達、供應鏈、產業圖解、大盤「產業即時」或個股頁的產業資訊前，先看這份。

數量會跟著資料變動，最新數字用 `node scripts/check-indpack.mjs --report` 看，不寫死在這裡。

## 三套分類

| 分類 | 來源 | 誰決定 | 一檔股票屬於幾個 | 用在哪裡 |
|---|---|---|---|---|
| **題材**（自建） | `learner/industry.js` 的 `INDUSTRY_MAP.themes`，加上 `learner/indpacks/*.js`（合併成 `industry-pack.js`、`industry-figs.js`） | 人工整理：產業鏈的一段，列「常被提到的代表公司」，不是完整名單 | 可以好幾個 | 供應鏈、產業圖解、產業網絡、資金雷達的「題材」板塊、個股頁「屬性與產業鏈」 |
| **官方產業別** | 證交所／櫃買中心公司基本資料（`api/_lib/_tw.js` 的 `INDUSTRY` 代碼表，`/api/daily?meta=1` 即時提供） | 交易所：上市依證交所《上市公司產業類別劃分暨調整要點》（33 類）、上櫃依櫃買中心《上櫃公司產業類別劃分暨調整要點》（30 類），兩套不完全相同 | 只有一個（在它掛牌的市場） | 資金雷達的「產業」板塊（每類至少 3 檔才列） |
| **櫃買產業價值鏈** | 櫃買中心「產業價值鏈資訊平台」，`scripts/tpex-ic.mjs` 每週寫入 `learner/data/tpex-ic.json` | 分類架構（產業 → 上中下游細分產業）由櫃買中心平台提供；每個細分產業底下的公司是平台收錄的關聯資料，**不是主管機關對公司實際業務的核定或認證**。本站另外濾掉興櫃與外國企業（-KY） | 可以好幾個 | 大盤「產業即時」（沒有檔案時改用題材） |

## 規則

1. **題材 id 是跨功能的主索引。** 供應鏈、產業圖解、產業網絡、資金雷達的題材板塊都用同一個 id（例：`tw-cowos`）。頁面之間互相連結時用 id，不用名稱比對。既有 id 不改名、不重複使用。
2. **官方產業別、櫃買價值鏈獨立保留**，不寫進題材資料，也不另存一份靜態對照表（兩者每天／每週更新，寫死會過期）。需要時從來源即時取。
3. **不同分類的金額不能相加。** 一檔股票可以同時算進好幾個題材和一個官方產業，各板塊加起來會大於全市場。畫面上不同分類要分開標示（資金雷達用 `kind`：題材／產業）。
4. **代表股和產業鏈參與公司是兩種關係。**
   - 代表股：題材 `segs` 裡的公司。資金雷達的題材板塊**只算這些**，金額是「代表股合計」，不是整個產業。
   - 產業鏈參與公司：圖解 `chain` 裡的公司（上下游、設備、客戶），代號收在 `INDUSTRY_XREF`。只用於圖解與找公司，**不算進資金雷達**。
5. **上市、上櫃的官方產業別分開看。** 兩個市場各有自己的類別表，名稱相近不代表同一類（例：上市「金融保險」、上櫃「金融業」）。`_tw.js` 的 `INDUSTRY` 是兩個市場共用的代碼→名稱字典，不是某一個市場的類別數；月營收名冊實際出現的類別數（`--report` 可看）也不等於官方類別總數。
6. **只有台股題材有法人資金資料。** 美股、日股、韓股題材不顯示資金區塊，也不顯示成 0。
7. **櫃買價值鏈的「架構」和「公司關聯」要分開看。** 產業與細分產業的節點是平台的分類架構；公司出現在哪個節點是平台收錄的資料，畫面上只能寫成「櫃買產業價值鏈平台列在…」，不能寫成官方認定這家公司做這項業務。
8. **不在櫃買價值鏈裡不代表代號有錯。** 櫃買價值鏈不是完整公司名冊；代號是否有效要對照證交所／櫃買中心的公司名冊。
9. **資料缺值照既有規則**：拿不到就是「沒有資料」，不當成 0。板塊加總只加有資料的股票；成分股全部缺值時顯示「—」，部分缺值時要寫出有幾檔有資料。月營收名冊查不到只代表「名冊裡沒有」，是否下市要對照交易所公告。
10. **主計總處《行業統計分類》只當定義參考，不拿來分類公司。** 它的分類對象是「場所單位」的主要經濟活動，目前沒有可公開取得、逐公司對到細類的官方資料；經濟部的公司登記「營業項目代碼」是行政管理用的另一套，也不能轉成行業細類。不要把上市櫃公司對到主計總處的細類，也不要在畫面上寫成「主計總處認定」。公司實際業務若要分類，屬於本站自己的判讀，要附證據、期間與可信程度，不能標成官方認定（討論見 Issue #284）。

## 檢查

- `node scripts/check-indpack.mjs`：題材欄位、圖解、代號格式；每個題材都要有圖解；產業網絡引用的題材 id 都要存在。有 ✗ 會失敗，`tests/unit.test.mjs` 會跑。
- `node scripts/check-indpack.mjs --report`：另外印出分類盤點，只是清單、不算錯誤：
  - 沒放進任何產業網絡的題材；
  - 圖解產業鏈比代表股多出的台股代號數；
  - 不在櫃買價值鏈裡的代表股；
  - 沒有近期月營收的代表股（可能已下市、合併或改名；用 `learner/data/twse-rev.json`、`tpex-rev.json`，這兩份不含 -KY）；
  - 名稱和名冊不同的代表股、代表股的官方產業別分佈。
- 新增或修改題材（indpacks、`industry.js`）後跑一次 `--report`，看有沒有新出現的可疑代號。
