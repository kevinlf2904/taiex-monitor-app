# 績效分析（第 5 階段 A：計算引擎）

實作：`learner/perf.js`（`window.KLPerf`，要先載入 `ledger.js`）；測試：`tests/perf.test.mjs`。

這個 PR 只做計算引擎，不改畫面，也不讀寫任何存檔。績效畫面是下一個 PR（第 5 階段 B）。

## 1. 計算口徑

| 項目 | 口徑 |
|---|---|
| 範圍 | 只看**證券部位**（股票、ETF 的市值），不含現金 |
| 現金流 | 「投入」與「拿回」的錢：<br>• 買進付出的錢（含手續費、稅）算投入<br>• 賣出拿回的錢（扣掉手續費、稅）、領到的股息（扣掉預扣稅）、零股結算的現金算拿回<br>• 股票轉入、轉出依當天市價計算 |
| 價格 | **原始收盤價**。股息已經當成現金流記錄，再用還原價會重複計算 |
| 幣別 | 台幣、美元分開算，不相加（匯率是第 3 階段） |
| 時間加權報酬（TWR） | 每天的報酬＝（今天收盤市值 − 今天淨投入）÷ 昨天收盤市值 − 1，每天連乘。淨投入用**實際成交金額**（含費稅），等同把現金流放在收盤後：當天「成交價 → 收盤價」的漲跌算進當天報酬。前一天市值是 0（第一天，或出清後重新買）時，報酬＝收盤市值 ÷ 投入 − 1。不受投入時點影響，用來和大盤比 |
| 資金加權報酬（MWR） | 投入時點與金額會影響結果。滿一年給年化 XIRR（`value`）；未滿一年只給整段期間的值（`period`），不年化 |
| 年化 | 期間滿一年才年化，未滿一年不年化，因為短期年化會誇大到沒有意義。期間用**實際有投資的期間**：從第一天算到最後一個還有市值或現金流的日子。已出清的部位，價格資料再長，也不會被算成投資滿一年 |
| 交易日曆 | 持股價格日、比較基準的交易日、現金流日，算到「資料日」為止。持股停牌或缺資料時，會用前一個收盤價，並標「價格過期」 |
| 月、季、年報酬 | 把每天的 TWR 依月、季、年連乘 |
| 最大回撤 | 用 TWR 淨值指數算從前高跌了多少，附前高日、谷底日。恢復時間是谷底到第一次回到前高的天數，還沒回到就是 null |
| 比較基準 | 同一段期間、同樣的日期。加權指數是價格指數，不含股息，結果會標 `priceIndex` |
| 總投入 | 買進與轉入的金額加總（`invested`），另外列出拿回的錢（`returned`）與淨投入 |
| 總損益 | 已實現＋未實現＋股息（稅後）− 另計費用（例如股息匯費）＋其他公司行動的現金。買賣的手續費和稅已經算在成本與已實現裡，不重複扣。另計費用和公司行動現金同時計入現金流，報酬率和損益可以對帳 |
| 總報酬率 | 總損益 ÷ 總投入 |

## 2. 不硬算：估算與無法計算

資金加權報酬只有在現金流完整時才是 `status: "ok"`。下面這些情況會標成 `estimated`，並在 `reasons` 列出原因，畫面要顯示「估算」與原因：

| 原因代碼 | 說明 |
|---|---|
| `legacy_transfer` | 有從舊庫存轉入的部位，當時的買進日期與金額不一定準 |
| `transfer_at_cost` | 股票轉入那天沒有市價，用成本當投入金額 |
| `transfer_out_no_price` | 股票轉出那天沒有價格 |
| `history_truncated` | 價格歷史比第一筆交易晚開始 |
| `price_fallback` | 有些日子沒有收盤價，用最近一筆交易的價格代替 |
| `stale_prices` | 有價格停在超過 7 天前，例如停牌或資料缺漏 |
| `transfer_out_prev_price` | 股票轉出那天沒有收盤價，用之前的收盤價；`issues` 會記下用的是哪一天 |
| `pending_confirm` | 有部位合股後的零股還沒結算，股數與成本是暫時的 |
| `other_action` | 有其他公司行動的現金，需要確認性質 |

算不出來時標成 `unavailable`，不給數字，常見兩種情況：
- 只有投入、沒有市值。
- 現金流正負來回好幾次，有不只一個解（`multiple_solutions`）。程式會在 −100%～+1,000,000% 之間掃描變號區間；若現金流有多次正負反轉，即使掃描只找到一個或零個根，也不宣稱唯一解（因有限網格可能漏掉切線根或非常接近的根），而是標示無法確認。

整體狀態依嚴重程度排序：
1. `has_errors`：有錯誤的交易，沒有算進去。
2. `needs_confirm`：有待確認的部位。
3. 各幣別的 `estimated`。
4. `ok`。

畫面要明確顯示目前是哪一種。

## 3. 歸因

- **每一檔**：已實現＋未實現＋股息＋歸屬到這一檔的另計費用、公司行動現金，以及占總損益的比例。
- **對不到任何一檔的費用、現金**：列在 `unattributed`。所有個股加總，再加上未歸屬，等於總損益。
- **依資產類型、產業加總**：由呼叫端傳 `classify` 提供分類。
- **另外列出**：股息、費用與稅的合計。
- **匯率影響**：還沒有資料（`fx: null`），要等第 3 階段。

## 4. 畫面（第 5 階段 B）

位置：庫存 →「交易紀錄」→「績效」（`learner/ledger-ui.js`；`perf.js` 用到時才載入，樣式也在 `ledger-ui.js`，不用改 `watch.html`）。

- 價格：每一檔用 `/api/kline` 原始收盤（24 個月）；比較基準是加權指數（台幣）、SPY 還原價（美元）。10 分鐘內重複使用，可按「重新載入價格」。
- 重點數字：總損益與總報酬率、時間加權報酬（滿一年附年化）、資金加權報酬（估算或無法計算會標示）、最大回撤與恢復、相對比較基準。
- 走勢圖：組合（實線）和比較基準（灰色虛線）同一起點＝100；「全部」的起點是第一筆投入前，其他範圍的起點是範圍前一天的收盤，所以圖上的報酬和上面的數字一致。回撤畫在另一張圖（不用雙軸）。
- 日期範圍：3 個月、6 個月、1 年、全部。滑鼠或手指在圖上移動，顯示當天的組合、比較基準、回撤、市值。圖下有給螢幕閱讀器的數值表。
- 月報酬表：時間加權、紅漲綠跌、顏色深淺代表幅度；停在格子上看比較基準；交易日少於 15 天的月份會註明。
- 誰賺誰賠：每一檔的損益長條（以 0 為中心），以及依類型、產業、股息、費稅的合計；匯率影響註明還沒有。
- 計算口徑：可展開的說明。
