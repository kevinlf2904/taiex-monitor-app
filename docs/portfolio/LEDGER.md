# 交易紀錄引擎（第 4 階段 A）

實作：`learner/ledger.js`（`window.KLLedger`，都是純函式）；測試：`tests/ledger.test.mjs`。

這個 PR 只做計算引擎：
- 不讀、不寫任何存檔。
- 不改畫面，網頁也還沒有載入這支檔案。

交易紀錄畫面和寫入新存檔是下一個 PR（第 4 階段 B）。

## 1. 一筆交易

| 欄位 | 說明 |
|---|---|
| `id`、`v` | 唯一編號、資料版本（1） |
| `date` | 交易日期 `YYYY-MM-DD`（不能是未來，也不能早於 1990 年） |
| `type` | 交易類型，見下表 |
| `symbol`、`market`、`currency` | 代號；市場 `tw`／`us`；幣別 `TWD`／`USD`（必須和市場一致，同一個代號前後也要一致） |
| `shares`、`price` | 股數（台股要整數，美股可以有零股）、成交價格（轉入時是每股成本） |
| `amount` | 股息、入金、出金、另計費用的金額 |
| `ratio` | 拆股或合股的比例：一股變幾股。一拆四填 4，五合一填 0.2 |
| `fee`、`tax` | 手續費、交易稅。**沒填**才依規則估算，並標示 `feeEstimated`；**填 0** 就是 0 |
| `assetType`、`dayTrade` | `stock`／`etf`、是否現股當沖（影響證交稅） |
| `ref` | 另計費用對應的是哪一筆交易 |
| `note`、`source` | 備註；資料來源（`manual`、`legacy`、`import`、`broker`） |

交易類型：

| 類型 | 中文 | 怎麼處理 |
|---|---|---|
| `buy` | 買進 | 成本 = 股數 × 價格 + 手續費 + 稅 |
| `sell` | 賣出 | 已實現損益 = 股數 × 價格 − 手續費 − 稅 − 賣掉部分的成本 |
| `dividend` | 現金股息 | 另外記錄（扣掉預扣稅），不改成本 |
| `stock_dividend` | 配股（除權） | 股數增加、成本不變，所以平均成本下降。有填配股率（`ratio`，配 1 元股票股利＝0.1）時，會和持股核對，對不上就提醒 |
| `split` | 拆股／合股 | 股數乘上比例、成本不變。台股合股後不足一股的部分標成待確認（`pending`），整本帳狀態是 `needs_confirm` |
| `fraction_cash` | 零股現金結算 | 拿掉不足一股的部分和它的成本，拿到的現金和成本的差額是已實現損益，待確認的標記也會清掉 |
| `transfer_in` | 股票轉入 | 依填的每股成本加入，不動現金 |
| `transfer_out` | 股票轉出 | 依成本拿掉，不算已實現損益 |
| `deposit`、`withdraw` | 入金、出金 | 只動現金 |
| `fee` | 另計費用 | 對應買賣（`ref`）的費用併進那筆交易：買進算進成本、賣出從已實現損益扣，和日期先後無關。其他交易的費用（例如股息匯費）記在那一檔 |
| `other` | 其他公司行動 | 依填的股數變動、金額處理，一律提醒確認。只有金額時可以不填代號，只記現金 |

同一天的交易：拆股、配股這類公司行動先生效（除權日一開盤就生效），其他交易照輸入順序處理。

## 2. 成本計算

- `avg`（加權平均成本）或 `fifo`（先進先出）。一本帳只用一種，存在 `method`，不能混用。
- FIFO 會列出每一批還沒賣掉的股數與成本（`lots`）。
- 每一筆交易後都會留下股數、總成本、平均成本的紀錄（`history`），用來顯示「個股成本變化」。

## 3. 費用規則

- `DEFAULT_RULES` 依市場分開，每一項都附來源與日期。
- 計算一律從 `rules` 讀，可以整份換成使用者券商的條件，例如手續費折扣、最低手續費。
- 台股預設：
  - 手續費 0.1425%，最低 20 元，無條件捨去。買進、賣出可以設不同折扣（`discountBuy`、`discountSell`）。
  - 證交稅：股票 0.3%、ETF 0.1%、債券 ETF 0（停徵，到期日請依法令確認）、現股當沖 0.15%。
- 美股預設：
  - 零佣金。
  - 股息預扣 30%。
  - SEC 規費預設 0，請依券商對帳單填寫。
- 估算的費用會標示「估算」，不會說成實際費用。
- `feeDiff(tx)`：使用者填了實際費用時，算出和規則估算差多少，用來檢查券商條件設定。

## 4. 資料驗證

| 狀況 | 結果 |
|---|---|
| 賣出或轉出超過當時持股 | 錯誤，不套用 |
| 股數不是大於 0 | 錯誤 |
| 台股股數不是整數 | 錯誤 |
| 價格無效 | 錯誤 |
| 日期不存在、在未來、早於 1990 年 | 錯誤 |
| 幣別和市場不一致 | 錯誤 |
| 同一代號前後的市場或幣別不一致 | 錯誤 |
| 交易編號重複 | 錯誤 |
| 兩筆內容完全一樣 | 提醒，可能重複輸入 |
| 另計費用對應的交易已經有手續費，或同一筆交易有兩筆另計費用 | 錯誤（`duplicate_fee`），避免重複計算 |
| 另計費用和對應交易的日期不同 | 提醒 |
| 合股後有不足一股的部分 | 提醒，並標成待確認，直到記入零股現金結算 |
| 配股股數和配股率對不上 | 提醒 |
| 沒有持股卻領股息 | 提醒 |
| 有記入金或出金，但現金是負的 | 標示 `cash.negative` |

錯誤的交易不套用，其他交易照常計算，整本帳的狀態會是 `has_errors`。下一個 PR 的畫面在有錯誤時不允許存檔。

## 5. 統計

- 每個代號都有：股數、總成本、平均成本、已實現損益、股息、手續費、稅。
- 有現價才算未實現損益；沒有現價時是 `null`，不是 0。
- 現金和總計依幣別分開，台幣和美元不相加。
- 有記入金或出金，現金才算「有追蹤」（`tracked`）。很多人不記現金，所以沒有入金紀錄時不會報錯。

## 6. 新增前預覽與刪除影響

- `previewAdd(list, tx)`：先試算這筆交易會不會出錯，例如賣超。
- `deleteImpact(list, id)`：列出刪除後會受影響的後續交易、刪掉後才出現的錯誤，以及持股前後的變化。畫面上要先顯示這些，再請使用者確認刪除。

## 7. 舊庫存搬移預覽

- `previewMigration(raw, { today })`：把舊庫存 `kline:watch:hold` 的每一筆變成一筆「股票轉入」，成本用當時記的平均成本。
  - 範例持股和錯誤資料不搬，並寫出原因。
  - 沒有建倉日期的，先用搬移當天，並標示出來。
- 只產生預覽。`store` 是確認後要寫進 `kline:pf:v1` 的內容，格式是 `{ v: 1, method, transactions, migratedFrom, at }`。
- `validateStore(store)`：寫入前、讀出後都要跑，檢查版本、成本方法，以及每一筆交易能不能套用。
- 舊鍵 `kline:watch:hold` 保留不刪，保留規則見 `DATA_CONTRACT.md`（在 PR #225）。

## 8. 引擎與介面能力（第 4 階段 B ＋ 截圖匯入）

- 交易紀錄畫面：
  - 新增、編輯交易（先試算，錯誤擋下、提醒再確認）。
  - 刪除交易：先確認，並顯示影響範圍（後續受影響筆數與持股變化）。
  - 交易歷史、個股成本變化（FIFO 亦顯示剩餘批次）。
  - 已實現與未實現損益、現金股息、手續費與稅統計；「全部／台股／美股」市場篩選。
- 搬移流程：先預覽，使用者按確認後才寫入 `kline:pf:v1`，舊鍵 `kline:watch:hold` 保留不動。
- 雲端同步、備份檔同時支援 `kline:` 開頭資料（`checkBackup` 驗證版本與完整交易檢查）。
- 券商截圖匯入（`api/_lib/import.js` ＋ `prepareHoldingsImport` / `prepareTradesImport`）：
  - **選項 1（庫存／持股截圖 `mode: "holdings"` → `transfer_in`）**：
    - 解析股數（保留美股小數股數）與平均成本（或依市值／損益推算），`fee: 0, tax: 0, source: "import"`。
    - 比對 `kline:pf:v1` 現有未平倉部位：目前尚有持股的代號預設不勾選（`on: false`）並標示「帳本已有 N 股，預設略過以免重複」；未持有或已全數賣出者預設勾選；使用者仍可手動勾選或切換「包含帳本已有部位」。
    - 未含日期時帶入今天並標記待確認標籤。
  - **選項 2（成交明細／對帳單截圖 `mode: "trades"` → `buy` / `sell`）**：
    - 保留同一天、同代號、同價格的分批成交（不去重合併）。
    - 解析完整日期、民國年與缺年份日期（`dateAssumed: "year"` 標記「年份待確認（請核對）」；缺日期 `dateAssumed: "today"` 標記「未含日期，已帶入今天」）。
    - 手續費與交易稅嚴格區分：明確填 `0` 維持 `0`，空白（`null`）依規則估算（`feeEstimated: true`，賣出區分股票／ETF／債券 ETF／現股當沖 `dayTrade` 稅率）。
    - 降冪或同日賣在前、買在後明細先按時間由舊到新正規化再試算，擋下實際賣超、幣別衝突與無效欄位，偵測到可能重複交易時須明確勾選確認後方可寫入。

## 9. 畫面（第 4 階段 B）

- 位置：庫存 →「交易紀錄」分頁，程式在 `learner/ledger-ui.js`，用到時才載入（`LAZY.ledger`）。
  - 2026-11 起庫存只有一排主分頁：總覽｜持股（損益、屬性分析）｜績效｜配置與風險（配置、風險、總經敏感度、融資）｜股利｜論點｜交易紀錄。
    原本「交易紀錄」底下的第二排分頁（總覽、績效、配置、股利、融資、論點）搬到這一排；內部狀態仍是 `W.holdView`＋`W.lg.view`，對照表在 `watch.html` 的 `HOLD_NAV`。舊名稱對照：即時損益＝持股→損益，持股分析＝持股→屬性分析。
- 第一次使用與截圖匯入入口：
  - 首次使用頁：提供「從現有庫存建立（先預覽）」、「截圖匯入（持股／對帳單）」、「從空白開始」。
  - 已有交易紀錄時：「交易紀錄」操作列與「持股」分頁上方提示條（`holdSrcBar` 的「截圖匯入」）皆可開啟雙模式截圖匯入對話框（`#impSheet`）。
  - 第一次由截圖匯入建立帳本時可選成本算法（`avg`／`fifo`）；已有帳本時沿用原設定不覆蓋。
- 舊庫存 `kline:watch:hold` 完全保留不刪也不改。
- 新增、修改與截圖匯入在寫入前皆透過 `KLLedger` 試算，錯誤（賣超、日期不對、指數／非支援市場代號、幣別衝突等）會擋下並標註對應欄位，沒通過 `validateStore` 不寫入；交易明細偵測到 `possible_duplicate` 時須勾選確認。
- 刪除交易：如果刪掉後別的交易會出錯，就不讓刪；否則先顯示影響範圍（後續筆數、持股與成本的前後變化），確認後才刪除。
- 台幣、美元分開統計。每一檔可以展開看成本變化表；用 FIFO 時也列出還沒賣掉的批次。
- 雲端同步與備份檔本來就包含所有 `kline:` 開頭的資料，新存檔會一起同步、備份。注意：單筆超過 150KB 的資料不同步，交易很多時之後要再處理。
- 仍需依實際券商條件手動補充：
  - 新增與匯入時空白費用目前以預設費率（手續費無折扣、一般證交稅）估算；若券商有電子下單折扣請於「手續費」欄實填或匯入後編輯。
