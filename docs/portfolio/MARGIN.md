# 融資與擔保品風險（第 7 階段）

- 實作：`learner/margin.js`（`window.KLMargin`，純函式）
- 畫面：庫存 →「交易紀錄」→「融資」（`learner/ledger-ui.js`，用到時才載入 `margin.js`）
- 測試：`tests/margin.test.mjs`、`tests/e2e/margin-ui.test.mjs`

## 1. 最重要的原則

- **結果一律是「試算」**：用使用者填的借款、門檻，加上目前報價計算。畫面寫明「不是券商的正式追繳通知或可借額度」。
- **每個帳戶都標資料來源**：`broker`（券商資料）、`user`（自己填的）、`estimate`（系統估算）。
- **門檻由每個帳戶自己設定**：追繳線、補足到、處分線、最高成數，並記錄來源與日期。
  - 沒有設定時才用預設值，畫面會要求改成自己券商的條件。
  - 預設值只是常見規定，不代表所有券商、所有商品都一樣：
    - 融資：維持率 130% 追繳、補足到 166%、成數 6 成
    - 不限用途借貸：130% 通知、120% 處分

## 2. 存檔

- 位置：`kline:pf:margin:v1`，內容是 `{ v: 1, accounts: [...] }`，和交易紀錄分開存放。
- 寫入前先跑 `validateStore`，下列情況會擋下、不寫入：
  - 借款不是正數
  - 年利率不在 0～100%
  - 「補足到」低於追繳線
  - 擔保品格式錯誤
  - 帳戶編號重複
  - 沒有任何擔保品（至少要有一檔股票或現金擔保）
- 雲端同步與備份檔本來就包含所有 `kline:` 開頭的資料，這個存檔也會一起同步、備份。

## 3. 計算

| 項目 | 算法 |
|---|---|
| 維持率 | 擔保品市值（股票＋現金擔保）÷ 借款 |
| 擔保品價格 | 優先用現價。沒有現價時用手填價格，結果標「估算」；兩者都沒有就不算進市值，狀態為「不完整」。價格日期超過 5 天也標「估算」。每一檔的價格、價格日期、來源都顯示在畫面的擔保品表 |
| 狀態 | 沒有借款＝`invalid`；沒有任何擔保品，或有擔保品沒有價格＝`incomplete`；用了手填價格或價格過期＝`estimated`；其餘 `ok` |
| 利息 | 借款 × 年利率 × 天數 ÷ 365（單利，從開始日算到今天） |
| 可用額度 | 擔保品市值 × 最高成數 − 借款（有設定成數才算） |
| 再跌多少會追繳 | 1 −（追繳線 × 借款 − 現金擔保）÷ 股票擔保品市值；處分線也用同樣算法 |
| 要補多少 | 低於追繳線時，補現金或還款到「補足到」的水準 |
| 壓力測試 | 股票擔保品同時下跌 5／10／15／20／30%，現金擔保不跌。另外算每一檔擔保品單獨連續三根跌停（約 −27.1%）的情況，找出風險最大的一檔 |
| 狀態 | 依維持率分為：正常、接近追繳線（追繳線 ×1.1 以內）、低於追繳線、低於處分線 |
| 期限 | 超過期限或 30 天內到期時，會提醒 |

## 4. 還沒做

- 從券商對帳單匯入。
- 多檔擔保品之間的相關性情境，例如用 Beta 模擬大盤下跌。
- 融券。
- 美元借款。
