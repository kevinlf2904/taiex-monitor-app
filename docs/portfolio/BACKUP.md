# 投資組合的匯出、備份與還原（第 10 階段）

沿用既有的「工具 → 備份同步」功能，不另外做一套備份。這次補上投資組合需要的部分。

## 1. 匯出

| 方式 | 內容 | 能不能匯回 |
|---|---|---|
| 交易紀錄 →「⬇ 匯出 CSV」 | 每一筆交易一列，欄位是中文，依日期排序（`KLLedger.toCSV`） | 不能，給 Excel、Numbers 看 |
| 工具 → 備份同步 →「匯出備份檔」 | 所有設定與紀錄，包含交易紀錄（`kline:pf:v1`）、對帳快照與稽核（`kline:pf:recon:v1`）和融資帳戶（`kline:pf:margin:v1`） | 可以 |

CSV 的處理：
- 檔案開頭加 BOM，Excel 才認得 UTF-8 中文。
- 欄位裡有逗號、引號時，會照 CSV 規則跳脫。
- 文字欄位如果以 `= + - @` 開頭，前面會加 `'`，避免試算表把它當成公式執行（CSV 注入）。

備份檔的處理：
- 格式版本 `v: 2`。舊的備份檔沒有 `v`，照樣可以匯入。
- **投資組合資料不管多大都會放進備份檔。** 以前超過 150KB 的資料會被默默略過，交易一多就可能漏掉；當 `kline:pf:recon:v1` 觸及 120KB 核心上限保護時亦提示先匯出 JSON 備份。

## 2. 匯入（還原）

1. 備份檔的版本比這個網站新，就不匯入，請先更新網頁。
2. 備份檔裡有投資組合資料時，會先用 `KLLedger.checkBackup`（並於載入 `recon.js` 後進行深度檢查，支援鍵序無關檢查）驗證：
   - 交易紀錄：用 `validateStore` 檢查版本、成本算法，以及每一筆交易能不能套用（有參考對帳快照時採 `buildReconciledLedger` 一併檢核）。
   - 對帳與快照存檔（`kline:pf:recon:v1`）：一定載入 `KLRecon.validateStore` 檢查欄位型別、市場／幣別衝突（`currency_conflict`）、快照／衝突有效性，嚴禁圖片與超過 2000 字元 base64 編碼；**若本機目前存在未恢復之 `pendingCommit`（WAL）即拒絕匯入還原**；備份檔若含未完成之 `pendingCommit` 則預設拒絕，僅在使用者二次確認剔除 WAL 並通過配對驗證後才允許匯入。
   - **單鍵備份與本機存檔配對保護**：匯入不含 `kline:pf:recon:v1` 的舊版備份（僅含 `kline:pf:v1`）且本機已有對帳快照時，會詢問是否一併清除本機對帳快照（選保留時強制將備份 `pf:v1` 與本機 `recon:v1` 成對跑 `checkBackup` 檢查，衝突即拒匯）；反之備份僅含 `kline:pf:recon:v1` 時亦強制連同本機 `kline:pf:v1` 成對檢查。
   - 融資帳戶：一定先載入融資模組（`margin.js`，使用者可能從沒開過融資頁），再用 `KLMargin.validateStore` 完整檢查借款、利率、擔保品、門檻、帳戶編號。融資模組載入失敗，或沒有檢查程式時，不降級成只看版本，整份不匯入。
   - 不認得的 `kline:pf:` 資料（可能是比較新的版本）：為了安全不匯入。
   - **只要有任何一項沒通過，整份都不匯入**，這台裝置的資料保持原樣。
3. 確認視窗會列出備份檔的交易筆數、對帳快照檔數、日期範圍，以及這台現在的資料將被取代。
4. 雙鍵或局部寫入時如果失敗（例如儲存空間不足），沿用原子回滾機制恢復原值；僅在匯入或同步資料涉及 `kline:pf:`／`PF_PAIR` 鍵時才透過 `withPfCommitLock`（`navigator.locks`）加鎖與檢查雙鍵 CAS，純自選或設定同步在無 `navigator.locks` 環境下仍可正常運作。

## 3. 雲端同步

- 雲端同步以 `PF_PAIR`（`pf:v1` ＋ `pf:recon:v1`）**成對上傳、成對還原**，並於同步還原前執行與備份還原相同等級之 `checkBackup` 驗證。
- 本機存在未恢復 `pendingCommit`（WAL）期間自動暫停對帳相關雲端上傳，避免把半成品推送覆寫雲端基準；單筆超過 150KB（或 `kline:pf:recon:v1` 超過 120KB 核心上限）時「備份同步」頁會顯示提醒，請改用備份檔保存。
