# 投資組合的匯出、備份與還原（第 10 階段）

沿用既有的「工具 → 備份同步」功能，不另外做一套備份。這次補上投資組合需要的部分。

## 1. 匯出

| 方式 | 內容 | 能不能匯回 |
|---|---|---|
| 交易紀錄 →「⬇ 匯出 CSV」 | 每一筆交易一列，欄位是中文，依日期排序（`KLLedger.toCSV`） | 不能，給 Excel、Numbers 看 |
| 工具 → 備份同步 →「匯出備份檔」 | 所有設定與紀錄，包含交易紀錄（`kline:pf:v1`）和融資帳戶（`kline:pf:margin:v1`） | 可以 |

CSV 的處理：
- 檔案開頭加 BOM，Excel 才認得 UTF-8 中文。
- 欄位裡有逗號、引號時，會照 CSV 規則跳脫。
- 文字欄位如果以 `= + - @` 開頭，前面會加 `'`，避免試算表把它當成公式執行（CSV 注入）。

備份檔的處理：
- 格式版本 `v: 2`。舊的備份檔沒有 `v`，照樣可以匯入。
- **投資組合資料不管多大都會放進備份檔。** 以前超過 150KB 的資料會被默默略過，交易一多就可能漏掉。

## 2. 匯入（還原）

1. 備份檔的版本比這個網站新，就不匯入，請先更新網頁。
2. 備份檔裡有投資組合資料時，會先用 `KLLedger.checkBackup` 檢查：
   - 交易紀錄：用 `validateStore` 檢查版本、成本算法，以及每一筆交易能不能套用。
   - 融資帳戶：檢查格式和版本。有 `KLMargin` 時，也用它的 `validateStore` 檢查。
   - 不認得的 `kline:pf:` 資料（可能是比較新的版本）：為了安全不匯入。
   - **只要有任何一項沒通過，整份都不匯入**，這台裝置的資料保持原樣。
3. 確認視窗會列出備份檔的交易筆數、日期範圍，以及這台現在有幾筆、會被取代。
4. 寫入時如果失敗（例如儲存空間不足），沿用原本的機制：已經寫入的部分會改回原本的值。

## 3. 雲端同步

- 雲端同步仍然不同步單筆超過 150KB 的資料（伺服器有大小限制）。
- 交易紀錄或融資資料超過 150KB 時，「備份同步」頁會顯示提醒，請改用備份檔保存，不會默默漏掉。
