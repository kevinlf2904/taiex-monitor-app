# 資料來源與更新標示（第 9 階段）

程式：`learner/pfsrc.js`（`KLPfSrc`，純函式）；畫面在 `learner/ledger-ui.js`（`pfSrcHtml`）與 `learner/pf-home.js`。測試：`tests/pfsrc.test.mjs`、`tests/e2e/pf-src.test.mjs`。

## 每一頁都有一行資料狀態
總覽（報價、融資擔保品報價）、配置（報價）、績效（日 K）、融資（擔保品報價）在資料區塊上方顯示：

| 項目 | 內容 |
|---|---|
| 來源 | 伺服器回傳的來源，例如「證交所 MIS」「富果」「Yahoo Finance」；日 K 是各檔的來源 |
| 即時／盤後 | 即時、盤後、定時更新（可能延遲，美股）、日收盤（日 K） |
| 行情日期 | 這批資料本身的日期範圍（不是抓取時間） |
| 取得時間 | 這次從伺服器拿到的時間（台北） |
| 完整嗎 | 幾檔都有，或 `n/m 檔`＋缺哪幾檔 |
| 過期嗎 | 沒有行情日期、比同市場其他持股最新的行情日舊、或比今天早超過 5 天 |
| 其他 | 用了備援來源（可能延遲）；離線快取（sw.js 存的舊資料） |
| 計算時間 | 另外寫，不和行情時間混在一起 |

等級：全部正常 ⓘ；有缺、過期、沿用、備援、離線快取 ⚠︎；這次整批拿不到 ✕。有問題時旁邊有「重新載入」。

## 更新失敗
- 不覆蓋最後有效資料：這次沒拿到的代號、基準指數、匯率、ETF 成分股沿用上一次的，並標示「沿用 MM-DD HH:MM 取得的資料」。連續失敗時沿用時間仍是最初拿到的時間。
- 上一次也沒有的代號不補資料，照樣標「缺」，計算時用成本估算並在總覽、配置標示（原本的行為）。
- 整批失敗時 3 秒後自動重試一次；再失敗就停，等使用者按「重新載入」（重新載入時不用本機 API 快取）。
- 重新載入時先留著上一次的資料在畫面上，新資料到了才換。

## 沒有改變的
- 不新增存檔鍵，資料只放在這次開啟網頁的記憶體裡。
- 不改 API；只用 `/api/quote`、`/api/kline` 本來就回傳的欄位（source、updateMode、dataDate、fetchedAt、isFallback、swCachedAt）。
