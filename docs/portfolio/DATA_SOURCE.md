# 資料來源與更新標示（第 9 階段）

程式：`learner/pfsrc.js`（`KLPfSrc`，純函式）；畫面在 `learner/ledger-ui.js`（`pfSrcHtml`）與 `learner/pf-home.js`。測試：`tests/pfsrc.test.mjs`、`tests/e2e/pf-src.test.mjs`。

## 每一頁都有一行資料狀態
總覽（報價、融資擔保品報價）、配置（報價）、績效（日 K）、融資（擔保品報價）在資料區塊上方顯示：

| 項目 | 內容 |
|---|---|
| 來源 | 伺服器回傳的來源，例如「證交所 MIS」「富果」「Yahoo Finance」；日 K 是各檔的來源 |
| 即時／盤後 | 即時、盤後、定時更新（可能延遲，美股）、日收盤（日 K） |
| 行情日期 | 這批資料本身的日期範圍（不是抓取時間） |
| 取得時間 | 這次從伺服器拿到的時間（台北） |
| 完整嗎 | 幾檔都有，或 `n/m 檔`＋缺哪幾檔 |
| 過期嗎 | 沒有行情日期；比同市場其他持股最新的行情日舊；或行情日期到今天之間隔了任何一個**交易日**（週末、休市日不算，台股春節長假後的最後收盤價仍是有效的）。交易日曆不知道的日子 →「無法確認是不是最新」，不當成正常 |
| 其他 | 用了備援來源（可能延遲）；離線快取（sw.js 存的舊資料） |
| 計算時間 | 另外寫，不和行情時間混在一起 |

等級：全部正常 ⓘ；有缺、過期、無法確認、沿用、備援、離線快取 ⚠︎；這次整批拿不到 ✕。有問題時旁邊有「重新載入」。

### 交易日曆
- 台股：證交所「開（休）市日期」表（`/api/calendar?hol=1`，網頁本來就會載入；只有今年的，跨年的日子視為不知道）。
- 美股：`core.js` 的美股休市日（固定規則計算）。
- 「今天」：台股用台北日期，美股用紐約日期。最多往回看 40 天，再舊就算過期。

## 更新失敗
- 每一檔各自記一筆：行情日期、來源、即時／盤後、取得時間。沿用時整筆照舊，所以連續部分失敗時，沿用的那檔仍標**當初真正取得的時間**；不同時間沿用的分開寫。
- 整批失敗時，上一次的來源、即時／盤後、行情日期都還在（來自沿用的那幾筆），只是「這次的取得時間」空白。
- 不覆蓋最後有效資料：這次沒拿到的代號、基準指數、匯率、ETF 成分股沿用上一次的，並標示「沿用 MM-DD HH:MM 取得的資料」。
- 上一次也沒有的代號不補資料，照樣標「缺」，計算時用成本估算並在總覽、配置標示（原本的行為）。
- 整批失敗時 3 秒後自動重試一次；再失敗就停，等使用者按「重新載入」（重新載入時不用本機 API 快取）。
- 重新載入時先留著上一次的資料在畫面上，新資料到了才換；手動重新載入後再給一次自動重試。
- 同時有兩次請求時，只有最新一次的結果能寫回（晚回來的舊請求丟掉）。
- 標示模組（`pfsrc.js`）載入失敗：價格照樣顯示、照樣沿用，狀態列改成「資料狀態標示沒有載入，無法確認資料來源與是不是最新」。

## 沒有改變的
- 不新增存檔鍵，資料只放在這次開啟網頁的記憶體裡。
- 不改 API；只用 `/api/quote`、`/api/kline` 本來就回傳的欄位（source、updateMode、dataDate、fetchedAt、isFallback、swCachedAt）。
